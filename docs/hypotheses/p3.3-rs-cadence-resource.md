## 0. Problem (closed by P3.2 probe `6aa50dc`)
`_rs_features` computed inter-tick intervals from `group["datetime_utc"]`, which on
the parquet path is built from snapshot `TickTime` (`ingest_parquet._clean_snapshot`,
~3 s resolution). Result: `rs_burst_ratio ≡ 0` for every parquet stock-day — the
sub-100 ms cadence signal was **absent, not dead**. The true sub-100 ms event clock
lives in the `deal` (`DealTime`) and `order` (`OrderTime`) tick streams.

**Hypothesis (P3.3):** re-sourcing `rs_burst_ratio` / `rs_interval_cv` /
`rs_split_similarity` from the deal/order tick clock will make the burst signal real
and improve capital classification (esp. the 量化→游资 leakage on up-days).

## 1. What was built (lands regardless of gate verdict)
TDD, minimal diff, parquet-only; xlsx/local untouched (fall back to snapshot clock).
- `config.RS_CADENCE_SOURCE: Literal["snapshot","deal","order"]` — selects the clock
  on the parquet path. **Default `"snapshot"`** (= pre-P3.3 behaviour).
- `ingest_parquet.read_deal_times_parquet` / `read_order_times_parquet` (+ private
  `_deal_time_maps` / `_order_time_maps`) — one batch read per stream; deal keeps
  genuine prints (`Side∈{0,1}`, `vol>0`), order keeps every event's `OrderTime`.
- `features._rs_features(group, rs_event_times_ms=None)` — when ≥2 distinct external
  HHMMSSmmm events are supplied, decode via `_hhmmssmmm_to_ms` (boundary-correct —
  a raw int diff over-counts minute/second rollovers), sort-unique, diff; else fall
  back to the snapshot clock.
- Threaded `rs_timestamps_lookup` through `aggregate.build_feature_matrix` →
  `compute_daily_features`; wired both parquet builders
  (`validate_offline._build_parquet_matrix`, `pipeline_parquet.build_feature_matrix_for_panel`)
  to pick the lookup by `RS_CADENCE_SOURCE`.
- 10 new tests (6 features, 4 ingest). Full suite: **186 passed, 2 xfailed** (was 176).

## 4. Why it regresses (the signal is real but mis-aligned)
A6 passes — re-sourcing genuinely revives the burst signal (deal mean 0.36, order
mean 0.51, vs ≡0 on snapshot). But A2/A3 **fail by ≈0.15** and 量化 recall on the
full set collapses 0.66→0.28. The new RS cadence does **not** align with the
rank-direction assumptions baked into `DIMS_QUANT` / `DIMS_YOUZI`
(`rules.py:42–59`), which were validated against the *degenerate* snapshot state
where RS contributed ~neutrally. With a live, panel-varying burst/CV signal, the
rank-normalised RS dims now actively pull true-量化 toward 游资 — the exact leakage
P3 §7 warned about ("best separates 散户 vs {游资,量化}; does **not** cleanly fix
量化→游资"). The 0625 量化→游资 boundary is unmoved (recall stays 1/6).

Deal and order produce **identical** capital F1 despite different burst magnitudes —
after cross-panel rank-normalisation the two clocks induce the same argmax ordering,
so the choice between them is moot here.

## 5. Verdict & disposition
**NO-SHIP.** Primary fallback taken: **revert the active source to `snapshot`**
(default already set). The re-source capability lands fully (config-gated, tested)
so future work can consume the now-available true tick clock — but only after the
`DIMS_QUANT`/`DIMS_YOUZI` rank directions are re-derived against the *live* RS
distribution (this is the real, larger task; flipping the source alone is net-negative).

The narrower fallback ("remove `rs_burst_ratio` from `DIMS_QUANT` only") was **not**
pursued: under the shipped `snapshot` source `rs_burst_ratio≡0` already contributes
~neutrally, and the regression is driven by all three RS dims under deal/order
(notably `rs_interval_cv`, which is in *both* youzi and quant dim sets), not by
`rs_burst_ratio` in `DIMS_QUANT` alone. Removing one dim would neither restore the
deal/order gate nor change the shipped snapshot baseline.
